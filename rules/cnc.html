CNC rules — the Stepcraft 840 D3 and UCCNC

Back to ../../CLAUDE.md · ../CNC_Machining_Guide.md

The hand-written NCs (cad/exports/cnc/lumi_wand_heatsink.nc, cad/exports/cnc/ArmPiUltra_Servo_BasePlate*.nc) and the generated base-plate NC (cad/freecad/gen_baseplate_nc.py) all have to satisfy the same syntax rules or UCCNC refuses to load the file — or worse, loads it and plunges with a dead spindle. Four workshop trips were lost between 2026-07-13 and 07-18 learning these one at a time (5928ab5, 3fc6d9f, a4ddc30, 5439025, 8a61bc9).

  • Comments are (...) block style, one line each — never ;. Our UCCNC install silently drops some ; lines; stick to Mach3-canon.
  • No ( or [ inside the body of any (...) block. Both open the lexer and a wrapped close is a load error. Substituting one for the other just moves the failure — strip both.
  • ASCII only (Windows-1252 codepage). °, Ø, ×, →, en/em dashes, smart quotes, non-breaking space all crash the parser with the same "Error reading line N" the bracket cases give — don't mistake one for the other.
  • CRLF line endings. UCCNC on LF-only reads the whole file as one line and the error-line number becomes nonsense.
  • Delete every T# M6 line. On this manual-tool-change install the M6 macro consumes the next S...M3, the spindle never starts, and the first plunge snaps the bit. Keep the (T# = ...) description for the on-screen tool identity.

gen_baseplate_nc.py E() applies all five rules on every emit; a regen can't reintroduce them. For hand-edited NCs, verify before the file is loaded on the Stepcraft: zero non-ASCII bytes, zero ;-starting lines containing ()[], zero T# M6 lines, zero lone-LF line endings. All four counts must be zero.

Operator rules that cost parts or cutters:

  • Every M0 pause must be followed by S...M3 + G4 Px dwell before any G1/G2/G3 cut. 2026-07-18, the OP3 slot NC was going to plunge a fresh SHARPRO bit with a dead spindle; 67d2f27 added the restart.
  • Re-touch Z=0 on the new endmill at every tool-change M0. Not optional — the SHARPRO tip sits at a different axial position than the Milwaukee drill's split point, and the OP3 breakthrough is only 0.05 mm into the spoilboard. (Operator standing rule.)
  • Heatsink slot cuts in its own op, on an isolated puck. The v9.8.2 integrated per-pass slot detour broke a SHARPRO 1/8" bit on pass 2, 2026-07-17: the cutter hard-turned into the puck rim while surrounded by 60×60 stock and stalled. v9.9 (a1b5259) split the waste-removal M0 out so OP3 cuts a free-standing puck; v9.9.1 (0afb78f) retracts Z between the +Y and −Y wall cuts so a 1-flute O-flute can clear chips in a closed pocket.
  • Use a real split-point twist drill for axial pecks — never an endmill. A 2 mm SainSmart endmill snapped on hole #1 of the v1 servo-plate run. Canonical pilot is a Milwaukee 1/8" cobalt (HSS-Co M35/M42, 135° split point) in a 1/8" OZ8 collet. OP1 is written around it on both heatsink and base plate.
  • The Kodiak 1/8" 2-flute carbide (1/8" shank) is retired. The only 1/8" endmill on hand is the SHARPRO 1/8" O-flute, 1/4" shank, so every T1 → T2 swap on the heatsink and base-plate NCs is a real collet change 1/8" OZ8 → 1/4" OZ8, not just a bit swap.
  • The heatsink NC is hand-written and does not propagate from any macro. HEATSINK_OD lives in cad/freecad/lumi_wand_cyl_v1.py; the NC carries the arithmetic by hand. When HEATSINK_OD moves (Ø48 → Ø54 at v9.10, 50b3013 2026-09-18), the NC is rewritten by hand and docs/CNC_Machining_Guide.md §3 is swept behind it. The 2026-09 sweep (48994cd) caught the OP2 table still describing the Ø48 program — following the doc would have cut a 6 mm undersize puck. Treat the NC as the source of truth; the guide is a reader-aid.
  • Base plate holes are emitted in toolB (X-mirrored) coordinates. The NC viewer looks "wrong" by design — the operator's post-install flip of the finished plate about its long Y axis is what lands each hole at its designed position. Cross-check: for any drilled hole, world.X_after_flip = −machine.X must equal FILE.x − Cx.
