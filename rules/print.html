The Bambu project is generated, not hand-edited

cad/print/lumiAi_Complete.3mf is built by cad/print/build_lumiai_complete_3mf.py and checked by cad/print/verify_3mf.py.

  • Per-object print settings are regenerated from the script. Anything you set per-object in Bambu Studio is lost on the next rebuild — put it in PART_SETTINGS instead.
  • Filament slots and the print profile ARE preserved: the script reads them from the live file, so operator edits in Bambu Studio survive. Only the carried-over meshes come from the donor.
  • Plate membership is decided by position, and Bambu lays plates out ceil(sqrt(n)) columns wide — so adding or removing a plate reshapes the grid and moves every object. Re-run the script; never drag parts between plates.
  • Plate names become gcode filenames: <>:/\|?*" are rejected and the error does not say which plate.

Orientation and filament

  • The extension halves stand on OPPOSITE ends. +Y prints flange-end down (776.6 mm² of bed contact); −Y prints PEG-end down (297.9 mm²). Flange-end down on −Y gives 3.0 mm², because the 2.5 mm v9.8 clocking tab stands proud of the flange face and the part balances on it.
  • The lens plate must never be printed in translucent filament; clear material pipes light between the towers and the beam check becomes useless.

Tree supports — forked by material

The thinned set below is the PLA set. Thin branches snap instead of tearing, which is what you want in PLA and a failure in PETG: thin PETG branches snap at the trunk junctions during the print.

The builder owns the fork: --material pla (default, the X1C book lumiAi_Complete.3mf) sets the thinned set below as the global profile; --material petg (the H2S book lumiAi_Complete_PROD_H2S.3mf) sets tree_strong, Ø5 branches, 2 walls, angle 35, support_speed 50, support_top_z_distance 0.4 instead. PART_SETTINGS entries that enable supports carry their own per-object set, so a PETG object in the X1C book can be tree_strong too. Do not hand-mix the two sets on one object.

Tree supports — thinned so they come OFF (the PLA set)

Objects set enable_support=1 in PART_SETTINGS; these values tune every thin-tree part from one place. The problem being solved is removal, not support failure — dense trees around the internal driver pads, L-tabs and PCA wedges tangle and mangle on the way out.

⚠️ support_object_xy_distance stays at 0.5 deliberately. The guide lists 0.40, but that is an increase from Bambu's 0.35 default; this project already sits at 0.5. Reducing it would press branches harder onto the part. Bigger gap = easier release — do not "correct" it down to match the guide.

Still stubborn after a print? The next lever is tree_support_wall_count: 1 (hollow single-wall branches). Left at -1/auto for now.

🚨 Every plate of both books is Textured PEI, with glue, on both printers. The plate-level bed_type is what Studio sends to the printer. A plate sliced for a bed other than the one installed stops the printer (plate mismatch), so check the installed plate before sending. ENG_PLATE_SLOTS in the builder is empty; a slot put in that set sends its plates to the Engineering Plate and tags their names E+G.

🚨 Support settings only bite as PER-OBJECT overrides. Put them in model_settings.config as <metadata> on the object — the same channel the rest of PART_SETTINGS uses. Setting them in project_settings.config or in a process preset does not work, and fails silently. Confirmed by setting them by hand in Bambu: it wrote them onto the object, nowhere else. The builder applies SUPPORT_TUNING to every thin-tree part with enable_support=1, so there is one place to edit. Bambu writes only the delta from the resolved preset; the builder writes all of them, so the result cannot drift when a preset or its parent changes.

🚨 A key the live process preset does not CARRY is a key you have not set. process_settings_*.config declare inherits: 0.12mm Fine @BBL X1C. Any key the preset omits resolves from that system parent — project_settings.config is never consulted for it. Writing a value into project_settings alone does nothing. The builder writes every support key into every process preset, present or not, and verify_3mf.py warns when a watched key is absent from a preset, not merely different.

🚨 support_style must be SET, never assumed. Under tree_organic Bambu ignores the Tree-Slim branch fields entirely, so branch distance and branch-diameter-angle silently refuse to take and the UI shows the preset's numbers instead of the project's.

🚨 A saved process preset can silently overrule the project settings. Metadata/process_settings_*.config are presets saved inside the 3MF. The builder patches every preset, and verify_3mf.py fails the build if any preset disagrees with the active config on a watched key.

PETG and supports

⛔ Never print PETG with large support areas. It does not work. PETG welds to its supports where PLA releases, so a big supported face does not come off clean — it tears. Opening the gap to 0.3 mm helps and does not save you.

If a PETG part needs more than a token amount of support, reorient it or change the part — do not turn supports up.

⚠️ The vertical shell halves' MINIMAL-class supports (internal features + the gripper ear) DO print in PETG+, with the reinforced tree set and support_top_z_distance 0.4 (2 layers) — see the material fork above. verify_3mf.py enforces the line: PETG + supports is a hard FAIL unless the object carries tree_strong AND top-z ≥ 2 layer heights, in which case it is a warning to inspect after removal. A big supported FACE in PETG still tears; reorient those.

⛔ Never put a recess's FLOOR on the downward side. A pocket floor that faces down is a bridge, and in PETG it sags into webs. No support setting fixes that; only orientation or a design change does. The cartridge caps are flat discs printed outboard face down, with the Keystone pockets facing UP and the M8 boss as a separate hex nut.

Rule: a functional seating surface must be a TOP surface or the bed face — never a bridge. Before choosing an orientation, check which face each recess's floor ends up on, not just bed contact and support area.

Check before adding supports to a PETG part: measure bed contact and overhang in both orientations first. The flip is usually free and the supports never are.

Clearing a jam mid-print — do not touch the toolhead

⛔ When the printer pauses for a filament jam, clear the SPOOL, not the head. The X1C does not re-home on resume — it returns to where it believes it is. Any nudge to the toolhead or gantry while it sits parked becomes a permanent XY offset for every layer above.

A touched toolhead shows up as a layer shift partway up (6–7 mm on the cartridge caps), in the same direction at the same Z on every part of the plate: the whole coordinate frame moved, not the parts.

So: change one thing per print when you can. And if a print was paused and touched, check the part for a step before trusting it.

After a plate-type change, RUN THE PRINTER'S FULL CALIBRATION

After switching plate type (Engineering to Textured PEI), run the X1C's own full calibration before printing. Without it, PETG parts fail at the near side and edges while the middle prints clean. Per-print auto-levelling is not sufficient: it runs every time and the edges still fail. A centred test disc does not clear this either; it only covers the middle of the bed.

When a printer starts failing after a hardware change, run its built-in calibration before constructing a single theory. Z offset lives on the printer, not in Bambu Studio, on the X1C.

Gates before a book is installed or a plate is printed

Every gate exits 1 on FAIL. Slice first with python cad/print/gate_slice.py <book.3mf> --plate N --keep <dir> (Studio's own CLI slice; it FAILS on any warning, error or non-zero return code, and keeps plate_N.gcode for the G-code gates below). A check that only prints notes or warnings is not a gate: the table says which is which.

Gate Run Checks FAILS when
verify_3mf.py python cad/print/verify_3mf.py <book.3mf> package, on-bed containment, minimum z, collisions, plate bookkeeping, mesh integrity, preset agreement, PETG supports, brim, slot indices, plate and object counts, the 30 mm back-edge keep-out on X1C plates a stated rule breaks; judgement items (for example PETG+ strong trees, preset overrides) only warn
gate_slots.py python cad/print/gate_slots.py <book.3mf> --printer h2s|x1c A each slot against the printer's live AMS (filament id, type, colour); B each PETG slot's filament values against the Inland PETG+ table, or against its own PRESET_ROWS row when the slot's vendor names another spool (today: AliExpress HS PETG red); C each printed object's process against its slot's material rules (temperature inside the material's band, PETG outer wall at most 70 mm/s and the tree_strong support set, ASA with a brim) any A, B or C mismatch. Warnings only: an empty AMS tray, clear filament reported as white, a PETG value that differs only on another nozzle variant, PETG with avoid-crossing-walls off while the outer wall is within the limit
gate_floating.py python cad/print/gate_floating.py <book.3mf> --plate N [--gcode plate_N.gcode] rasters every object of the plate at its own layer height; a region with nothing under it on the layer below, and not on the bed, is floating. Regions of 0.1 mm² and up count (one 0.5 mm raster cell) any floating region. With --gcode each region is checked against the slice: nothing printed there = raster dust, extrusion on the layer below = covered; both are listed and dropped, and only a region that prints with nothing under it fails
gate_gcode_floating.py python cad/print/gate_gcode_floating.py plate_N.gcode [--reach 0.6] [--min-mm 3] [--cantilever 2] reads the slice, not the mesh: every part line (walls, bridges, top and bottom surface, solid infill, gap fill) must stand on extrusion within 0.6 mm below, on support within 1.2 mm, or bond sideways (up to 2 mm) to a line that does an island of floating lines totals 3 mm or more. Islands under 3 mm print as notes (an ooze dot) and do not fail
gate_breakaway.py python cad/print/gate_breakaway.py <book.3mf> --plate N --gcode plate_N.gcode [--name part] [--want 1] every break-away block (a separate shell under a pocket roof) has exactly --want empty layers (default 1) between its last layer and the roof's first, read from the slice a block has any other number of empty layers (0 welds it to the roof, 2 lets the roof string), a block has no roof extrusion above it, or the plate has no block

--want takes a list for a plate whose blocks differ (--want 1,1,2, one per block in order).

Break-away void. The CAD gap is not what prints: Studio includes a layer only when its mid-plane is strictly above a face, so the roof must sit at least 0.03 off every layer mid-plane (BRK_MID_CLR) for the slicer to leave one void layer. The gate's bed placement is calibrated per block on the block's printed top surface (Bambu ; FEATURE: Top surface, matched to the mesh box within 3 mm, otherwise offset 0); the output prints the offset for each block.

gate_slots.py values (the same on both printers; --no-ams skips A and runs B and C only; --ams <json> reads a saved AMS read instead of a live one; the tables are at the top of the file, there is no --list):

  • PETG, Inland PETG+ (any colour, the default row): nozzle 235 or 240, flow 0.94, max volumetric speed 10 or 15 (another nozzle variant that differs only warns), retraction 1 mm / 40 / 70 % on both printers. Process: outer wall at most 70 mm/s; avoid-crossing-walls on (a warning when off, a failure when the outer wall is also over the limit); supports only as tree_strong with branch Ø5, 2 walls, support speed 50 (the wand flange coupons are sanctioned slim).
  • PETG, a named spool: its PRESET_ROWS row, keyed by type and the slot's filament_vendor, carries its own values and temperature band and falls back to the Inland PETG+ checks for anything it does not list. Today's row: AliExpress HS PETG red (X1C slot 2 from 2026-11-14), 240 / 0.94 / 10, band 230-260, qualified on the X1C 27 seat coupon.
  • Temperature bands (TEMP_BAND, nozzle temperature of every printed object against its slot's material): PLA 195-230, PETG 225-250, ASA 245-275, PA-CF 250-300, TPU 210-240. A material without a band (PAHT-CF) is not temperature-checked by this gate.
  • ASA: a brim is required (brim_type other than no_brim).
  • Slots fed from outside the AMS (H2S 5 and 6, and a one-slot book for an external spool) have no tray, so A skips them.

A project that moves to another material gets its PROCESS re-checked, not only its slots (C does this).

Where the gates run. gate_slots (live AMS) before any book or project is installed or sent. After a CAD change that touches a printed export: gate_floating --gcode and gate_gcode_floating on every changed plate, and gate_breakaway on every plate with break-away blocks. A plate that fails one of them waits for CAD to fix the model.

Review flow

  • Every CAD push is reviewed by 3dPrint for printability and by the CTO for the rows (the plate and BOM rows) before any rebuild of a book.
  • Cradle work, the catch latch included, is routed to 3dPrint / CAD by the operator's standing order. The CAD session leaves the cradle and catch macros alone.

Bambu Studio re-save drops the repo's settings

Open the repo book and send with Send without Save. A Studio re-save rewrites the book and drops the repo's settings.
